9097:   In order to avoid the cost of setting up new connections to backend servers
9098:   for each HTTP request, HAProxy tries to keep such idle connections opened
9099:   after being used. These connections are specific to a server and are stored
9100:   in a list called a pool, and are grouped together by a set of common key
9101:   properties. Subsequent HTTP requests will cause a lookup of a compatible
9102:   connection sharing identical properties in the associated pool and result in
9103:   this connection being reused instead of establishing a new one.
9104: 
9105:   A limit on the number of idle connections to keep on a server can be

9107:   periodically purged according to the "pool-purge-delay" interval.
9108: 
9109:   The following connection properties are used to determine if an idle
9110:   connection is eligible for reuse on a given request:

9112:   - proxy protocol

9115:     "pool-conn-name" expression if present, otherwise by the "sni" expression,
9116:     which defaults to "req.hdr(host),field(1,:)", i.e. uses the incoming
9117:     request's "Host" header field without the colon nor the port number.
